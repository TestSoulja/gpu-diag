# AGENTS.md — GPU Diag

Память проекта: только то, что нельзя вывести из кода. Правила работы, границы,
где доказательства. Факты о коде — в `src/`, текущее состояние — в `docs/acceptance.md`.

## Что это

- Один публичный репозиторий: `TestSoulja/gpu-diag`, лицензия MIT.
- Инструмент для владельца компьютера с Windows 10/11, у которого время от времени
  пропадает изображение: отчёт, фоновая запись телеметрии, несколько обратимых правок
  питания. Всё это один PowerShell-скрипт и два файла рядом с ним.
- Две папки, один репозиторий:
  - `C:\VS\gpu-diag-staging` — **стейдж**: здесь правки, прогоны, коммиты и теги;
  - `C:\VS\gpu-diag` — **зеркало** опубликованного состояния: правок, коммитов и
    тегов в нём нет; `dist\` хранит только архив, скачанный с GitHub Release.
    `build.ps1` в зеркале не запускать.
- «Прод» здесь — публикация из стейджа: `push` + аннотированный тег `v<версия>` +
  GitHub Release с ассетом `GPU-Diag.zip`. Только по отдельному слову владельца.
  «Сделай» про код публикацией не считается.
- После публикации зеркало переводится на новый тег: `git fetch --tags`,
  `git reset --hard v<версия>`, затем в `dist` кладётся тот же архив, что загружен
  в Release, и sha256 сверяется с ассетом.

## Версия

- Единственный источник версии — `src/GPU-Diag.ps1` (`$script:Version`).
  Вторая копия версии где-либо запрещена: ни в README, ни в docs, ни в скриптах.
- Тег = `'v' + версия`, аннотированный, ровно на HEAD релизного коммита.
- После релиза README/docs-коммиты сдвигают HEAD — это нормально. `check.ps1` считает
  тег корректным, если он аннотированный, является предком HEAD и
  `git diff <тег> HEAD -- src/` пуст. Изменился `src/` без новой версии — страж красный.
- Документация и машинный страж (`README*.md`, `docs/**`, `AGENTS.md`, `check.ps1`)
  версию не поднимают и тега не получают.

## Что считается продуктом

- `src/**` — продукт, который уезжает в архив. Любая правка `src` требует новой версии,
  записи в `CHANGELOG.md` и нового архива.
- `CHANGELOG.md` — для того, что видит владелец компьютера. Правки README, docs и
  стража в него не пишутся, версию не поднимают.
- Опубликованные релизы 1.2–1.5.4 не переписываются задним числом: ни тег, ни ассет.

## Зависимости и сервисы

- Зависимостей нет и не добавлять: только Windows PowerShell 5.1 и встроенные средства
  Windows. `check.ps1` не ходит в сеть и не требует прав администратора.
- Сторонние сервисы (CI, мониторинг, облака) не предлагать. GitHub Actions — только
  после «да» владельца.

## Файлы и кодировки

- Скрипты PowerShell — UTF-8 с BOM: без BOM Windows PowerShell 5.1 читает кириллицу
  как cp1251 и падает на разборе. Это `src/*.ps1`, `src/*.txt` и `check.ps1`.
  `src/START-HERE.bat` — намеренно без BOM: BOM ломает первую строку `.bat`.
- Переводы строк — по `.gitattributes`: CRLF для `.ps1`/`.bat`/`.txt`, LF для `.md`.
- Решения по git — по `$LASTEXITCODE`, а не по stderr: git пишет прогресс в stderr,
  а `$ErrorActionPreference = 'Stop'` считает это падением.

## Доказательства

- Публичный текст = факт: любая цифра — из команды или из кода, иначе её нет.
- `docs/acceptance.md` — что доказано машиной, что руками, что не проверялось.
  Непроверенное пишется как «не проверялось»; слов «работает» и «безопасно» там нет.
- `check.ps1` — машинный страж; на чистом дереве печатает `CHECK: N/N PASS`.
- `docs/history.md` — хронология по тегам; `docs/backlog.md` — долги и порядок;
  `docs/release.md` — процедура релиза.

## Быстрые проверки

```powershell
cd C:\VS\gpu-diag-staging
powershell -NoProfile -ExecutionPolicy Bypass -File .\check.ps1
git status -sb
git rev-parse HEAD; git rev-parse origin/main
git for-each-ref --format='%(refname:short) %(objecttype) %(*objectname:short)' refs/tags
Select-String -Path .\src\GPU-Diag.ps1 -Pattern "Version\s*=\s*'([0-9.]+)'"
(Get-FileHash .\dist\GPU-Diag.zip -Algorithm SHA256).Hash
```

Проверки — только в стейдже. В зеркале `check.ps1` (появится там после 1.5.5)
печатает предупреждение «это зеркало, работай в стейдже», но не падает.
