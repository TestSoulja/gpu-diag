# Бэклог

Долги с причиной и порядком. Сроков нет; порядок — сверху вниз.

1. **Абсолютное обещание в `src/README-RU.txt`.** Строки 6–8: «Он НЕ удаляет файлы,
   НЕ ставит программы и НИКУДА не отправляет данные в интернет» — тот же класс, что
   уже исправлен в `README.md`: инструмент регистрирует задачу планировщика и копирует
   движок в профиль, а единственное обращение наружу — поиск драйверов через службу
   Windows Update, и выполняет его сама Windows. Причина: публичный текст = факт;
   инструкция внутри ZIP не должна утверждать больше, чем делает код. Это `src/**` →
   правка только в версии 1.5.5+ (в этом шаге `src` не менялся).
   Строка 103 (поиск в Windows Update — «только сообщает, ничего не устанавливает»)
   верна и узка, долгом не является.

2. **Приватность не описана в инструкции внутри ZIP.** В `src/README-RU.txt` (раздел
   «Что внутри ZIP», строки ~158–171) перечислены файлы, но нет ни слова о том, что
   в `watch\gpu-watch.csv` пишется заголовок активного окна, а в `minidumps\` лежат
   фрагменты памяти. Человек, который распаковал архив, узнаёт об этом только из
   README репозитория. Причина: тот, кому архив передают, читает инструкцию внутри
   архива, а не GitHub. Это `src/**` → 1.5.5+.

3. **Машинный страж не запускается автоматически.** `check.ps1` есть и проходит на
   чистом дереве, но его запускает человек. Причина: без автозапуска забытая правка
   `src` без версии и CHANGELOG обнаружится только при следующем релизе. Автозапуск
   (CI) — только по «да» владельца; сторонние сервисы не предлагать.

4. **Ротация логов не сделана.** `gpu-watch.csv` ≈ 2–3 МБ в сутки и растёт без
   ограничения (`README.md`, раздел «Фоновая запись»); старый файл только
   переименовывается при смене формата колонок. Причина: многодневная запись занимает
   диск и увеличивает финальный ZIP. Правка `src/**` → новая версия, CHANGELOG, архив.

5. **Дампы в ZIP и их приватность.** В архив копируются до пяти `*.dmp` из
   `C:\Windows\Minidump` (папка `minidumps\`) — это фрагменты памяти.
   `live-kernel-reports.txt` содержит только список файлов `LiveKernelReports`, сами
   дампы оттуда не копируются. Причина: приватность и размер архива. Решение
   (оставлять, ограничивать, предупреждать) — за владельцем; правка `src/**` → 1.5.5+.

6. **AMD/Intel без `nvidia-smi`.** В README написано, что отчёт работает без
   live-телеметрии GPU, но на такой машине прогонов не было. Причина: неизвестно,
   не ломается ли отчёт на путях без `nvidia-smi`. Нужна машина и прогон; правок
   `src` это не требует, пока не найден дефект.

7. **CX/CI не решён.** Автоматическая проверка при push не настроена; GitHub Actions
   возможен только после «да» владельца. Сторонние сервисы (мониторинг, облака,
   панели) не предлагать — правило владельца от 24.11.2026.

8. **Что дальше по продукту** — списком, без обещаний:
   - прогон `-Mode SelfTest` под администратором (сейчас не проверялся);
   - откат правок пунктом 6 на живой машине;
   - реальный сбой экрана во время записи;
   - вторая машина;
   - удаление папки при живой задаче;
   - тексты `src/README-RU.txt` и состав ZIP после решения по ротации и дампам
     (правка `src` → 1.5.5+).
