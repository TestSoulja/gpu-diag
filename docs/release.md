# Процедура релиза

Релиз = `push` + аннотированный тег `v<версия>` + GitHub Release с ассетом
`GPU-Diag.zip`. **Публикация — только по отдельному слову владельца.** «Сделай» про
код, «закоммить» и даже `push` сами по себе релизом не считаются.

## Предусловия

1. Работа в `C:\VS\gpu-diag-staging` (стейдж), ветка `main`, дерево чистое, `main`
   не впереди и не позади `origin/main` (до начала релиза). В `C:\VS\gpu-diag` —
   зеркале опубликованного состояния — ничего не правится, не коммитится и не
   собирается.
2. Требуется новая версия, только если менялся `src/**`. Правки README, `docs/**`,
   `AGENTS.md`, `check.ps1` версию не поднимают и тега не получают.
3. Версия поднимается **в одном месте** — `src/GPU-Diag.ps1`, строка `$script:Version`.
   Второй копии версии быть не должно (это проверяет `check.ps1`).
4. В `CHANGELOG.md` есть раздел `## [<версия>] — <ГГГГ-ММ-ДД>` с текстом для владельца
   компьютера.
5. `check.ps1` на чистом дереве печатает `CHECK: N/N PASS` и возвращает 0.

## Шаги

1. Поднять версию в `src/GPU-Diag.ps1` (`$script:Version`), больше нигде.
2. Записать раздел `## [<версия>]` в `CHANGELOG.md`.
3. Прогнать страж:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\check.ps1
   ```
4. Собрать архив:
   ```powershell
   .\build.ps1
   ```
   Ожидается `dist\GPU-Diag.zip` с тремя файлами: `GPU-Diag.ps1`, `START-HERE.bat`,
   `README-RU.txt` (внутри папки `GPU-Diag`).
5. Записать SHA-256 собранного архива — это значение будет сверяться после загрузки:
   ```powershell
   (Get-FileHash .\dist\GPU-Diag.zip -Algorithm SHA256).Hash
   ```
   Полный SHA-256 собранного архива печатает и `check.ps1`, тест 5
   (`PASS 5 archive 3 files, zip <байты>, sha256 <64 символа>`) — его можно сверить
   с ассетом глазами, не пересобирая архив вручную.
6. Закоммитить изменения (версия, CHANGELOG), затем создать аннотированный тег **ровно
   на HEAD**:
   ```powershell
   git tag -a v<версия> -m "GPU Diag <версия>"
   git rev-list -n1 v<версия>   # должен совпасть с git rev-parse HEAD
   ```
   После релиза README/docs-коммиты сдвигают HEAD. Это нормально: `check.ps1` считает
   тег корректным, пока он аннотированный, является предком HEAD и
   `git diff <тег> HEAD -- src/` пуст. Если `src/` изменился, а версия не поднята,
   страж красный — значит, нужен новый релиз.
7. `push` ветки и тега — по слову владельца:
   ```powershell
   git push origin main
   git push origin v<версия>
   ```
8. Создать GitHub Release по тегу, вложения — тот же самый файл `dist\GPU-Diag.zip`,
   текст — раздел `CHANGELOG` этой версии. Загружать архив, собранный в шаге 4, а не
   пересобранный заново.
9. После загрузки сверить показанный GitHub SHA-256 с локальным из шага 5. Не совпало —
   перезагрузить ассет, а не пересобирать архив.
10. Обновить зеркало на выпущенный тег:
    ```powershell
    git -C C:\VS\gpu-diag fetch --tags
    git -C C:\VS\gpu-diag reset --hard v<версия>
    Copy-Item .\dist\GPU-Diag.zip C:\VS\gpu-diag\dist\GPU-Diag.zip
    (Get-FileHash C:\VS\gpu-diag\dist\GPU-Diag.zip -Algorithm SHA256).Hash
    ```
    Хеш в зеркале должен совпасть с ассетом, сверенным в шаге 9. В зеркале
    `build.ps1` не запускать: `dist` там — копия опубликованного архива, а не место
    сборки.
11. Сохранить `dist\GPU-Diag.zip` (он не в git) — по нему потом проверяется, что
    опубликован именно этот файл.

## Если что-то не так

- `check.ps1` красный — исправлять причину до тега. Тег на красном дереве не ставится.
- Тег уже создан, а релиз ещё нет — тег можно удалить локально и переставить; если тег
  уже ушёл в `origin`, он опубликован. Опубликованные релизы 1.2–1.5.4 не переписываются.
- Опубликованный ассет не совпал по хешу — это дефект релиза; решение (перезалить ассет
  или выпустить новую версию) принимает владелец.
- Пересборка старого релиза (до 26.11.2026) может дать другой SHA-256, если у файлов
  в `src` изменились mtime: старый `build.ps1` клал mtime файлов в ZIP, а `git checkout`
  меняет mtime. Это свойство ZIP до введения детерминированной сборки, а не признак
  подмены. Начиная с 26.11.2026 все записи получают одну фиксированную метку времени,
  и повторная сборка того же `src` даёт тот же SHA-256.
