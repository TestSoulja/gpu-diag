# Чек-лист поддержки

Что спросить у владельца ПК и что попробовать руками, пока фоновый логгер собирает данные.
Цель — за 10 минут отделить «проблема в мониторе/кабеле» от «проблема в ПК».

## 1. Вопросы (ответы отсекают половину версий)

1. Когда гаснет: только в играх/видео, или и в простое (браузер, рабочий стол)?
2. Что на мониторе: надпись «Нет сигнала / No signal», просто чёрный экран, или индикатор
   переходит в дежурный режим (оранжевый вместо синего)?
3. Звук в этот момент продолжается?
4. Клавиатура отвечает — Caps Lock загорается/гаснет?
5. Восстанавливается само, или нужна перезагрузка компьютера / передёргивание кабеля?
6. Кулеры в этот момент становятся громче?

### Как читать ответы

| Комбинация | Вероятная группа причин |
|---|---|
| «No signal» + звук идёт + Caps Lock работает | сигнал теряется: кабель, порт, монитор, реже драйвер |
| чёрный экран + звук пропал + Caps Lock не реагирует | завис/выключился весь ПК: питание, перегрев, память |
| индикатор уходит в дежурный режим | монитор не видит линк (DP/HDMI), часто кабель |
| только в играх | драйвер, питание GPU, БП |
| и в браузере/видео | кабель, линк, монитор, БП |
| кулеры резко громче + затем гаснет | перегрев или просадка питания |

## 2. Тест железом (по одному шагу, после каждого наблюдать)

1. Другой кабель (DP → HDMI и наоборот).
2. Другой разъём на видеокарте.
3. Её монитор — на другом компьютере/ноутбуке.
4. Другой монитор/телевизор — на её компьютере.
5. Один монитор вместо двух.
6. Частота обновления 60 Гц вместо высокой.
7. Полностью закрыть разгон и оверлеи (Afterburner, RTSS, Discord/NVIDIA/Steam overlay).

Тот шаг, после которого проблема исчезла, и указывает на виновника.

## 3. Что смотреть в присланном архиве

1. `report.txt` → раздел `FINDINGS` (вверху приоритеты HIGH/MEDIUM).
2. `report.txt` → `SYSTEM EVENT LOG`: наличие 4101/4102/4103 (TDR), WHEA, Kernel-Power 41,
   BugCheck, 6008.
3. `report.txt` → `CRASH DUMPS / LIVE KERNEL REPORTS`: WATCHDOG-дампы = 0x141.
4. `report.txt` → `APPLICATION LOG` → WER `P1=141/117`.
5. `report.txt` → `NVIDIA LIVE DATA`: `PCIe link` (gen/x), троттлинг, температура.
6. `report.txt` → `GRAPHICS / DRIVER REGISTRY`: `HwSchMode` (HAGS), `OverlayTestMode` (MPO).
   Даты для сравнения: `First display error` (SYSTEM EVENT LOG) и
   `Newest GPU driver package` (DRIVER HEALTH CHECK).
7. `watch\events.log` — события с контекстом GPU/CPU/PCIe в момент инцидента.
8. `watch\gpu-watch.csv` — окрестности метки времени инцидента: питание, частота, троттлинг,
   `pcie_gen`/`pcie_width` (просадка линии видна только здесь). Старый файл после смены
   формата лежит рядом как `gpu-watch-<таймстамп>.csv`.
9. `watch\thermal.csv` — троттлил ли CPU.

## 4. Матрица выводов

| Что нашли | Вывод |
|---|---|
| 4101/4102 или `P1=141/117` | сбой драйвера/движка: чистая установка драйвера, затем питание/GPU |
| WHEA 17/18/19 | аппаратная ошибка шины: слот, райзер, БП, BIOS |
| Kernel-Power 41 / 6008 | потеря питания: БП, кабели питания GPU, разгон |
| `PCIe link gen` ниже максимума | слот/райзер/посадка карты/питание |
| throttle `HwSlowdown`/`HwThermal` | перегрев или лимит питания GPU |
| события CPU id 37 | троттлинг CPU (перегрев/лимит питания) |
| ничего из перечисленного | кабель/монитор/линк — идти по п. 2 |

## 5. Если прислали только `report.txt`

Это уже даёт: модель GPU и драйвер, тип подключения монитора, настройки питания, историю
событий за 30 дней и все дампы. Не хватает только покадровой телеметрии вокруг инцидента —
её собирает пункт `4` меню.
